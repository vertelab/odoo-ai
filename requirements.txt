# ai_agent_core / ai_agent — Python dependencies
#
# Installeras av repo_apply (salt odoo.repo_apply) som samlar alla
# /usr/share/odoo-*/requirements.txt, deduplicerar och installerar.
# Verifieras efterat av scripts/verify_requirements.py — som gor staten ROD
# om ett paket har nedan saknas.
#
# VIKTIGT (driftlardom 2026-09-14/15):
#   `tenacity` saknades i drift i elva manader. Inget state var rod, och
#   forst nar AI-streamen (/ai/stream) anropades small det:
#       ModuleNotFoundError: No module named 'tenacity'
#   -> HTTP 500 pa varje AI-session. Orsaken var att repo_apply installerade
#   paketen men INTE verifierade dem. Verifieringen finns nu
#   (scripts/verify_requirements.py) och denna fil ar dess indata.
#
#   Av samma skal: skriv ALDRIG ett paket utan att det gar att importera.
#   Paketnamn != importnamn (python-docx -> docx, PyPDF2 -> PyPDF2).
#
# VIKTIGT om delade paket:
#   repo_apply installerar med `--ignore-installed`, dvs pip loser om HELA
#   beroendetradet fran scratch. Utan versionstak kan det da NEDGRADERA ett
#   paket som redan fungerar i drift. `cryptography` ar kankans exempel:
#   pyOpenSSL 22.0.0 kraver cryptography<39, medan Odoo 18 och moderna
#   libs kraver >=49. Att installera nagot som drar in cryptography utan tak
#   gav:  AttributeError: module 'lib' has no attribute 'GEN_EMAIL'
#   -> bruten TLS i hela Odoo. Darfor ar de tva ihoplasta nedan.
#
#   ANDRA FALLET (2026-10-29): `extendable-pydantic` 1.4.1 monkeypatchade
#   `pydantic._internal._generate_schema.get_type_ref` via en .pth-fil som
#   kors vid VARJE python-start. pydantic 2.14.0 flyttade funktionen till
#   `_type_refs` -> AttributeError i varje login-shell pa dms. Paketet drogs
#   in som transitivt beroende (extendable_fastapi -> extendable-pydantic)
#   och importerades aldrig av Odoo. Atgardat: 1.5.0 (monkeypatchar inte
#   langre) + tak nedan. Poangen: aven ett paket vi inte ber om kan sla
#   sonder pydantic for hela installationen.
